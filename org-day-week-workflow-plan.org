* Planning deliverable

This file, =/home/merrinx/Projects/emacs-flake/org-day-week-workflow-plan.org=, is the sole planning deliverable. It updates the existing plan in place after the confirmed decision to remove Org Agenda entirely. The pre-existing =README.org= is repository documentation, not another planning deliverable. No project source or configuration is changed during planning.

* Goal

Implement an agenda-free Org workflow with:

1. =~/Documents/notes/tasks.org= as the authoritative task source and operational task view.
2. Native TODO sparse trees inside =tasks.org= for all-open and state-specific review.
3. Existing Org-roam daily notes for a linked =Top 3=.
4. Weekly Org notes for linked =Outcomes= and written =Review=.

The workflow should make capture, daily selection, weekly review, and completion clear without Org Agenda buffers, Agenda configuration, a replacement dashboard, or duplicated TODO entries.

* Scope

- Make =~/Documents/notes/tasks.org= the sole configured destination for new task captures.
- Seed that file lazily with =Inbox= and =Actions= headings.
- Configure =TODO=, =NEXT=, =WAIT=, =DONE=, and =CANCELLED= states.
- Open and review the source task file directly with native TODO sparse trees.
- Add a daily command that opens today's Org-roam daily note and ensures one =Top 3= heading.
- Add a weekly command that opens an ISO-week note below =~/Documents/notes/Planning/= and ensures =Outcomes= and =Review= headings.
- Use stable =id:= links from planning notes to authoritative source task headings.
- Remove the existing Org-roam daily task capture template while preserving historical daily TODOs unchanged.
- Remove the Agenda section from the startup dashboard.
- Remove the now-unused =org-modern-agenda= finalization hook while retaining =org-modern-mode= in normal Org buffers.
- Add commands beneath the existing =C-x o= prefix without redefining it or replacing current bindings.

* Observable acceptance criteria

- Two task captures create exactly two TODO children below =tasks.org::* Inbox= and create no daily task entry.
- Repeated initialization preserves existing task-file content and never duplicates =Inbox= or =Actions=.
- Opening =tasks.org= and invoking native =C-c / t= shows unfinished =TODO/NEXT/WAIT= source headings; =DONE/CANCELLED= are excluded.
- Native =C-c / T= can select one state such as =NEXT= or =WAIT= without creating a generated task database or Agenda buffer.
- Sparse-tree operations alter folding only; they do not alter task text or the buffer's modified state.
- Opening today's planner twice leaves exactly one =Top 3= and preserves all existing daily-note content.
- Opening a weekly planner twice reuses one ISO-week file and preserves its =Outcomes= and =Review= content.
- A task linked from a planning note can be renamed, completed, and manually refiled within the canonical file without creating another task or breaking the link after save/reopen.
- Existing historical TODOs under =Backlog/= remain byte-for-byte unchanged. They are no longer automatically aggregated; direct opening or an explicit existing search command is required to find them.
- Existing =C-x o l/c/f/i/d/t/y/m= bindings and daily =d/l/j/m= capture templates remain unchanged; only the daily =t= task template is retired.
- The dashboard retains recents, bookmarks, and projects but has no Agenda section.
- Normal Org buffers still enable =org-modern-mode=, but executable repository modules contain no =org-agenda= integration, configuration, hook, or command binding.
- Loading configured Emacs in a fresh sandbox HOME does not create =Documents/notes= and the supported workflow creates no =org-agenda-mode= buffer.
- Besides this plan, implementation changes exactly the four files owned by =WS-01= and makes no package, flake, lockfile, persistent-test, or personal-note change.

* Explicit non-goals

- Using, configuring, binding, or displaying Org Agenda.
- Removing the Org package itself. Org remains required by tasks, capture, sparse trees, links, notes, and Org-roam.
- Patching or replacing upstream Org internals that happen to contain Agenda-named functions.
- Installing =org-ql=, =org-super-agenda=, or another task-query dependency.
- Building a replacement cross-file task dashboard, calendar, deadline-warning view, or automatic historical-task aggregator.
- Automatically selecting a Top 3, rolling tasks forward, rescheduling missed work, or migrating historical daily TODOs.
- Copying TODO keywords, schedules, deadlines, or completion checkboxes into daily or weekly notes.
- Adding project/context/effort metadata, habits, notifications, calendar synchronization, or a custom task picker.
- Adding persistent ERT/Nix test infrastructure.
- Adding Org to the deliberately minimal Emacs configuration.
- Editing files below =~/Documents/notes= during repository implementation or verification.

* Accepted trade-offs of removing Org Agenda

- There is no automatic date-oriented day view, Monday-to-Sunday task calendar, deadline warning list, or cross-file unfinished-task rollup.
- Scheduled and deadline metadata may remain on source tasks, but the supported workflow does not proactively surface it by date.
- Native TODO sparse trees filter the current =tasks.org= file by state, not by scheduling date. Future-scheduled unfinished tasks remain in an all-open or matching-state tree.
- Historical TODOs in =Backlog/= are preserved but no longer appear automatically during review. An explicit file open or text search is required.
- The plan deliberately accepts these limitations rather than recreating Agenda under another name.

* Recommended operating workflow

** Capture and triage

- Press =C-x o n= to capture a new action under =tasks.org::* Inbox=.
- During triage, press =C-x o T= to open the authoritative task file.
- Refile accepted work from =Inbox= to =Actions= with native =C-c C-w=.
- Set the source heading state with native =C-c C-t=:
  - =TODO=: accepted backlog.
  - =NEXT=: immediately actionable.
  - =WAIT=: blocked on a person or event.
  - =DONE= or =CANCELLED=: terminal.

** Plan and run the day

1. Press =C-x o T= to open =tasks.org=.
2. Use =C-c / t= for every unfinished source task, or =C-c / T= and choose =NEXT= for the focused action list.
3. Press =C-x o p= to open today's daily note.
4. Select at most three source tasks. At each source heading, press =C-x o s= to store an ID link, save the source, then insert it below =Top 3= with =C-c C-l=.
5. Complete the original source heading. The daily note remains a record of intent, not a second task list.

** Plan and review the week

1. Open =tasks.org= and use =C-c / t= to review all unfinished canonical tasks.
2. Process =Inbox= and explicitly inspect =NEXT= and =WAIT= with =C-c / T=.
3. Optionally inspect legacy =Backlog/= TODOs by opening known files or invoking the existing search command =M-x my/grep-in-files-from-root= with the Backlog directory and a state keyword. This is textual discovery, not a complete semantic task view.
4. Press =C-x o w= to open the current weekly note.
5. Record one to three observable results below =Outcomes=, linking to source tasks where useful.
6. At week end, record what finished, what remains, and what should change below =Review=.

** Restore the full task-file view

After a sparse tree, use the native Org visibility command =M-x org-fold-show-all= or ordinary Org cycling. Rerun the sparse tree when a refreshed selection is needed.

* Design decisions

** D-01: One task source of truth

All configured new task capture goes to =~/Documents/notes/tasks.org=. The user previously approved retiring the daily task template. Historical daily TODOs remain in place without migration.

** D-02: Remove Org Agenda entirely

The user explicitly selected removal of Org Agenda rather than removal of only the dashboard widget. The implementation removes project-authored Agenda configuration, rendering hooks, dashboard integration, command bindings, and supported Agenda-buffer workflows.

This decision does not remove Org's bundled source code or patch native commands that may internally call Agenda-named helpers. If “entirely” is later interpreted as zero transitive execution of any upstream Agenda-named function, implementation must stop because that conflicts with retaining normal Org refiling and ID behavior without patching upstream Org.

** D-03: Direct source plus native sparse trees

Use =tasks.org= itself as the task UI. Native =C-c / t= supplies the all-open view; =C-c / T= supplies state-specific review. Do not create a wrapper unless packaged Org behavior proves inaccessible from the configured keymap.

** D-04: No automatic historical aggregation

The former promise that legacy daily TODOs would automatically appear in weekly review is retired. Preserving it would require another cross-file aggregation system and undermine D-02. Historical files remain unchanged and can be opened or explicitly searched.

** D-05: Links, never copied task state

Daily/weekly notes contain prose and stable =id:= links, never copied TODO state. Task completion remains on the source heading.

** D-06: Lazy runtime creation

Configuration load defines values and commands only. Explicit task/planning commands may create their needed runtime paths. Existing files are never reseeded, silently repaired, or implicitly saved.

** D-07: ISO Monday week

Weekly files use =%G-W%V.org=. ISO week-year behavior around New Year is intentional even though no weekly Agenda exists.

** D-08: One implementation owner

A single backend specialist owns the four tightly coupled modules: task workflow, daily-template transition, removal of Agenda styling, and removal of dashboard Agenda display.

* Proposed interfaces and invariants

** I-01: Module integration

- New =emacs/modules/docs/org-planning.nix= uses order 1504, after =org-roam.nix= defines shared paths and =org-prefix-map=.
- It uses the existing module shape and automatic discovery.
- It must contain no =org-agenda*= references or Agenda-buffer workflow.
- Use named synchronous functions; do not change the generated full configuration's lexical-binding behavior.

** I-02: Task storage and initialization

Proposed function: =merrinx/org-planning-ensure-tasks-file () -> absolute pathname=.

- Resolve =tasks.org= below the existing notes root.
- Run only for explicit task open, capture, or refile-target resolution.
- Seed a missing file with =#+title: Tasks=, exactly one top-level =Inbox=, and exactly one top-level =Actions=.
- Inspect an already visiting buffer so unsaved user edits are not bypassed.
- Preserve existing content. Missing or duplicate required headings in an existing file produce =user-error= before insertion/refiling.
- Never overwrite an unsaved buffer merely because its backing file is absent.
- Propagate native filesystem errors and never fall back to another path.

Proposed function: =merrinx/org-planning-open-tasks ()=.

- Ensure and visit the source file, widen it, and reveal ordinary source content.
- Do not create an indirect/generated task buffer or save existing edits.

** I-03: Capture, lifecycle, and refiling

Proposed function: =merrinx/org-planning-capture-task ()=.

- Register one standard Org capture template under key =t= with target =(file+olp merrinx/org-planning-ensure-tasks-file "Inbox")=.
- Use =file+olp= so a nested heading named =Inbox= cannot be selected instead of the validated top-level heading.
- Create a =TODO= child with inactive capture timestamp and available source annotation, but no invented schedule or deadline.
- Capture cancellation creates no task; first use may leave the initialized empty task file.

Lifecycle:

#+begin_src emacs-lisp
((sequence "TODO(t)" "NEXT(n)" "WAIT(w)" "|" "DONE(d)" "CANCELLED(c)"))
#+end_src

- Use native completion timestamp logging.
- Configure native refile targets from the validated task file at level 1.
- Refile moves, never copies.
- Do not configure =org-agenda-files= as a refile or ID source.
- Remove only Org-roam's daily capture template =t=; retain =d/l/j/m= verbatim.

** I-04: Native source review

No custom review function is planned.

- =C-x o T= opens =tasks.org=.
- =C-c / t= runs native all-unfinished TODO sparse-tree behavior.
- =C-c / T= followed by =TODO=, =NEXT=, or =WAIT= filters one unfinished state.
- =DONE= and =CANCELLED= do not appear in the all-unfinished tree.
- Selection is state-based. A future-scheduled unfinished task remains visible.
- Ancestor/context headings exposed by native Org are allowed and do not represent copied tasks.
- Sparse-tree folding must not modify text or mark the buffer modified.
- Do not use tags/property match sparse trees if the packaged implementation invokes Agenda preparation; the TODO-tree branch is the supported path.

** I-05: Daily planner

Proposed function: =merrinx/org-planning-day ()=.

- Explicitly load the public Org-roam dailies API and invoke =(org-roam-dailies-goto-today "d")= to select the existing default template without prompting.
- Operate only after an actual daily file buffer is available.
- Widen and count exact top-level =Top 3= headings.
- Append one if absent, preserve one if present, and raise =user-error= before mutation if duplicates exist.
- Preserve =Log=, journal, meeting, and other existing content.
- Do not add TODOs, checkboxes, automatic selections, or implicit saves.

** I-06: Weekly planner

Proposed function: =merrinx/org-planning-week (&optional time)=.

- Format local time with =%G-W%V=.
- Visit =~/Documents/notes/Planning/<ISO-year>-W<ISO-week>.org=.
- Explicit invocation may create its directory and a missing file.
- A new file gets a title, =Outcomes=, and =Review=.
- For an existing file, preflight counts for both required top-level headings before inserting either. Append missing headings; duplicate required headings raise =user-error= with no partial repair.
- Reopening preserves prose/links and does not implicitly save edits.
- No date aggregation or calendar buffer is involved.

** I-07: Stable link flow without configured Agenda sources

- Require =org-id=.
- Set =org-id-link-to-org-use-id= to =create-if-interactive=.
- Set =org-id-extra-files= to the explicit canonical task pathname so ID recovery does not depend on configured Agenda sources.
- =C-x o s= invokes =org-store-link= at the selected source heading.
- The user saves the source, opens the daily/weekly note, and inserts the stored link with =C-c C-l=.
- Captions are descriptive text, not synchronized status.
- Guaranteed relocation scope is within =tasks.org= or a historical Backlog task manually moved into =tasks.org=. Arbitrary moves to unknown files are not guaranteed.
- Validation must test recovery with the source buffer closed and native ID-location state cleared; an already-open source buffer is insufficient evidence.

** I-08: Agenda integration removal

- =emacs/modules/docs/org-modern.nix=: remove only the =org-agenda-finalize= / =org-modern-agenda= hook; retain =(org-mode . org-modern-mode)=.
- =emacs/modules/visual/dashboard.nix=: remove only =(agenda . 5)=; retain recents, bookmarks, projects, and all other dashboard behavior.
- =emacs/modules/docs/org-planning.nix=: add no Agenda variable, command, custom view, hook, buffer, or key.
- Do not remove =org= or =org-modern= from =emacs/lib.nix=.

* Alternatives considered

** Keep Agenda but remove its dashboard widget

This preserved automatic date and cross-file views, but the user explicitly rejected it by choosing complete Agenda removal.

** org-ql or org-super-agenda

Both would add dependencies and another query/dashboard system. They would replace rather than simplify Agenda and are not present in the repository.

** Custom cross-file search buffer

A custom task scanner could preserve legacy rollups, but it recreates a task dashboard and introduces parsing, refresh, navigation, and performance concerns. Reject it.

** Existing textual search

Useful only as an explicit optional aid for legacy cleanup. It can match prose, depends on saved files/search rules, and is not a semantic source of truth.

** Column view

Native and source-oriented, but useful primarily when task properties are configured. The planned workflow has no property taxonomy, so it adds complexity without value.

** Copied Top 3 and weekly TODOs

They appear self-contained but create stale completion states. Reject in favor of stable links.

* Risks and mitigations

- Removing Agenda intentionally loses automatic deadline/date and historical rollups. Keep this visible as an accepted limitation; do not add a substitute aggregator.
- Native sparse trees review only the current task file. Keep =tasks.org= authoritative for new work and use optional explicit search only for legacy cleanup.
- A pre-existing incompatible =tasks.org= could be damaged by auto-repair. Validate strict headings and stop without mutation.
- Daily first-use capture may be asynchronous or leave a capture buffer. Test the public flow and do not mutate transient state as a finalized note.
- ID lookup may appear to pass only because the task buffer remains open. Close it, clear native location state, and retest in another process.
- Optional text search may report false positives or miss ignored/unsaved files. Do not make it an acceptance source.
- Existing external user customization could bind the proposed keys. Repository bindings are known; runtime conflicts must be reported rather than overwritten.
- Removing dashboard Agenda may expose package-version behavior not covered by build checks. Include an interactive startup smoke test.

* Stop conditions

The implementing lead must stop and report if:

- A required public Org/Org-roam API differs and the smallest alternative changes visible behavior.
- Existing =tasks.org= lacks or duplicates required headings.
- A proposed key replaces an existing repository binding.
- Correctness requires a fifth source/configuration file, new package, flake/lock change, or persistent test.
- Validation cannot isolate HOME, XDG, Org ID, and Org-roam state from real user data.
- Native sparse trees load or create Agenda buffers in the configured workflow.
- Stable canonical ID recovery fails with the source buffer closed and location state cleared.
- Removing Agenda integration breaks dashboard startup or normal Org styling and cannot be fixed within owned files.
- “No Agenda” is interpreted as banning all transitive upstream Agenda-named internals; that requires a new architectural decision.
